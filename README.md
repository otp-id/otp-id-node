# @otp-id/sdk

Official Node.js/TypeScript SDK for the [OTP.ID](https://otp.id) V3 API —
multi-channel OTP delivery and verification (WhatsApp, SMS, Voice, Email,
Missed Call, and WhatsApp Inbound) with prepaid billing.

[![CI](https://github.com/otp-id/otp-id-node/actions/workflows/ci.yml/badge.svg)](https://github.com/otp-id/otp-id-node/actions/workflows/ci.yml)

- Zero runtime dependencies — built on the native `fetch` and `node:crypto`.
- Faithful to the API: one method per endpoint, no hidden retries.
- Dual ESM + CJS build, full TypeScript types included — no `@types/*` package needed.
- Full API reference: https://docs.otp.id

## Install

```bash
npm install @otp-id/sdk
```

Requires Node.js >= 20 (uses the built-in `fetch` and `AbortSignal.timeout`).

## Quickstart

```ts
import { OtpIdClient } from '@otp-id/sdk';

const client = new OtpIdClient(process.env.OTPID_API_KEY!);

// 1. Send an OTP (code generated by OTP.ID, never returned to you).
const res = await client.requestOtp({
  channel: 'whatsapp',
  destination: '6281234567890',
  brand: 'MyApp', // shown in the OTP message; defaults to your merchant brand_name
  external_id: 'order-8821', // optional idempotency key
});
console.log('otp_id:', res.otp_id, 'balance:', res.last_balance);

// 2. Later, verify what the user typed.
const v = await client.verifyOtp(res.otp_id, '482913');
if (v.verified) {
  console.log('verified!');
} else {
  console.log('wrong code:', v.reason); // "mismatch" — not an error
}
```

(Top-level `await` shown for brevity — wrap the calls in an `async` function
if your entry point does not support it.)

## Error handling

Every non-success API response throws an `APIError`:

```ts
import { APIError, ErrorCodes } from '@otp-id/sdk';

try {
  const res = await client.requestOtp(params);
} catch (err) {
  if (err instanceof APIError) {
    switch (err.code) {
      case ErrorCodes.INSUFFICIENT_BALANCE:
        // top up first
        break;
      case ErrorCodes.DUPLICATE_EXTERNAL_ID:
        console.log('existing transaction:', err.details?.existing_otp_id);
        break;
      case ErrorCodes.RATE_LIMITED:
        // slow down (20 requests per second per API key)
        break;
    }
    return;
  }
  // network error, aborted signal, or SDK-side validation (empty API key / empty otp_id)
  throw err;
}
```

A wrong code on `verifyOtp` is **not** an error: the server answers HTTP 200
with `verified: false`, and the SDK resolves with
`{ otp_id, verified: false, reason: 'mismatch' }`. Expired, locked, or
already-used transactions do throw an `APIError`
(`OTP_EXPIRED`, `TOO_MANY_ATTEMPTS`, `ALREADY_USED`).

## Channels

| Constant | Value | Notes |
| --- | --- | --- |
| `Channels.WhatsApp` | `whatsapp` | `requestOtp` + `sendOtp` |
| `Channels.Sms` | `sms` | `requestOtp` + `sendOtp` |
| `Channels.Voice` | `voice` | `requestOtp` only |
| `Channels.Email` | `email` | `requestOtp` + `sendOtp` |
| `Channels.Misscall` | `misscall` | use `requestOtp`; user completes the caller's number |
| `Channels.WhatsAppInbound` | `whatsapp_inbound` | `requestOtp` only; user messages OTP.ID |

`Channel` is also a plain string union, so `channel: 'sms'` works without
importing `Channels`.

### Bring your own code

```ts
const res = await client.sendOtp('482913', {
  channel: 'sms',
  destination: '6281234567890',
});
```

### WhatsApp Inbound (user-initiated)

No code to type: show the user `res.verification.wa_link` and let OTP.ID
match their incoming message. Never call `verifyOtp` for these transactions —
detect completion via the `otp.verified` webhook or by polling `otpStatus`.

```ts
const res = await client.requestOtp({ channel: 'whatsapp_inbound' });
console.log('Ask the user to tap:', res.verification?.wa_link);
```

### Missed Call

The last digits of the calling number are the code. Show
`res.verification.prefix` and ask the user to complete the number, then pass
the completed digits to `verifyOtp`.

## Webhook: `otp.verified`

OTP.ID signs every webhook with `HMAC-SHA256(secret, timestamp + "." + body)`.
`parseVerifiedEvent` checks the signature (constant-time), rejects timestamps
outside ±5 minutes by default (replay protection, override with
`toleranceSeconds`), and decodes the payload. The example below uses plain
`node:http` — no framework dependency — and bounds the body read the same
way the client bounds API responses:

```ts
import { createServer } from 'node:http';
import { parseVerifiedEvent } from '@otp-id/sdk';

const MAX_BODY_BYTES = 1 << 20; // 1 MB

const server = createServer((req, res) => {
  if (req.method !== 'POST' || req.url !== '/webhooks/otpid') {
    res.writeHead(404).end();
    return;
  }

  const chunks: Buffer[] = [];
  let size = 0;
  req.on('data', (chunk: Buffer) => {
    size += chunk.length;
    if (size > MAX_BODY_BYTES) {
      req.destroy();
      res.writeHead(413).end();
      return;
    }
    chunks.push(chunk);
  });

  req.on('end', () => {
    const body = Buffer.concat(chunks).toString('utf8');
    try {
      const event = parseVerifiedEvent(
        process.env.OTPID_WEBHOOK_SECRET!,
        req.headers['x-otpid-timestamp'] as string,
        req.headers['x-otpid-signature'] as string,
        body,
      );
      console.log('verified:', event.otp_id, 'external_id:', event.external_id);
      res.writeHead(200).end();
    } catch {
      res.writeHead(401).end();
    }
  });
});

server.listen(3000);
```

## Configuration

```ts
const client = new OtpIdClient(apiKey, {
  baseURL: 'https://api.otp.id', // default
  timeoutMs: 10_000, // default 30_000
  fetch: myFetch, // inject a custom fetch implementation (tests, proxies)
});
```

The SDK never retries a request. If you add retries, only retry
`requestOtp`/`sendOtp` calls that carry an `external_id` (the server replays
them idempotently) — retrying without one may deliver a second OTP.

## TypeScript-first

Every wire type — `OrderParams`, `OrderResult`, `VerifyResult`,
`StatusResult`, `AccountResult`, `TopupResult`, `VerifiedEvent`, and more —
is exported from `@otp-id/sdk`. Field names stay `snake_case`, matching the
JSON wire format and the [API docs](https://docs.otp.id) exactly
(`otp_id`, `external_id`, `last_balance`, ...) — no camelCase remapping layer
to keep in sync with the server.

## Examples

Runnable examples for every channel live in [`examples/`](examples), mirroring
the flows above. They import the built package from `../dist/index.js`, so
run the build first:

```bash
npm run build

export OTPID_API_KEY=your_api_key
export OTPID_DESTINATION=6281234567890

node examples/whatsapp.mjs          # server-generated code via WhatsApp, then verify
node examples/sms.mjs               # server-generated code via SMS, then verify
node examples/voice.mjs             # spoken 4-digit code via phone call, then verify
OTPID_DESTINATION=user@example.com \
node examples/email.mjs             # server-generated code via email, then verify
node examples/misscall.mjs          # missed call — user completes the caller's number
node examples/whatsapp-inbound.mjs  # user sends a WhatsApp message; polls status until verified
node examples/send.mjs              # bring your own code (sendOtp) via SMS, then verify
```

> Every run creates a real transaction and charges credits on your account.
> Use a number you control.
